Check it yourself

The commands from the claims deck, as root on this machine. They print the same values as the rows above; a stranger can run them without asking us for anything.

$ cat /root/.ssh/authorized_keys
$ ssh-keygen -lf /root/.ssh/authorized_keys
$ passwd -S root
$ sshd -T | grep -i '^passwordauthentication'
$ getent passwd | grep -i odile
$ lsblk -f
$ DEV=$(cryptsetup status root_crypt \
| sed -n 's/^ *device: *//p')
$ cryptsetup luksDump "$DEV" \
| sed -n '/Keyslots:/,/Tokens:/p'
$ odile-support status
$ grep -c odile-support \
/root/.ssh/authorized_keys
$ sha256sum /usr/local/bin/odile-install.sh

And from your laptop, the report and the signed manifest. The report's JSON carries measurement, report_version and fetched_at; the manifest is the bytes the signature covers.

$ curl -s https://<slug>.odile.fyi/attestation
$ curl -s https://<slug>.odile.fyi/manifest
$ curl -fsSLO \
https://odile.fyi/releases/m1/odile-tenant.efi
$ sha256sum odile-tenant.efi

The manifest lists the Hermes commit, package versions, skill hashes, installer hash and model pin. It is signed with Odile's Ed25519 key; the public key is in your recovery kit and at https://odile.fyi/odile-signing-key.pub. This is an operator signature, not a hardware measurement; see gap 1.

The three gaps we state before anyone asks

  1. 1
    The app layer is not hardware-measured yet. Measured boot covers firmware, kernel, initramfs and command line. Hermes, the installer and the skills are pinned by a signed manifest and a published hash, but the CPU does not measure them. The installer is signed, inspectable and audited at handoff for keys, passwords and keyslots; only a measured image can prove there is no hidden backdoor. The manifest records the machine as provisioned; anything you install afterwards is yours.
  2. 2
    The console passes through the host. Serial and VNC can be watched. Never type a secret there; the sign-in goes over TLS to the guest, after the report checks out.
  3. 3
    Odile keeps three powers. We can stop or delete the machine (availability, not confidentiality); we control DNS for your slug (pin the certificate fingerprint in your recovery file — the one your machine first served; a renewal changes it) and we can set a different boot image from the panel (detectable via the measurement — compare it to the one in your ready email before you set your sign-in).
