### §4.1 — heading and text changed

**v3.7:** "The only SSH key is yours" — one key, the one you generated; the
initramfs accepts it.
**v3.9:** "**Zero usable user keys.**" `cat /root/.ssh/authorized_keys` shows
the throwaway public key from the measured command line (`/proc/cmdline`);
`ssh-keygen -lf` shows its fingerprint. Its private half was never written, so
no one can use it. There is no user key, no operator key, no shared account.

### §4.2 — last sentence changed

**v3.7:** "Servury's panel has no guest agent and cannot reset root. The only way
in is the user's key."
**v3.9:** "Servury's panel has no guest agent and cannot reset root. There is no
operator account; the only sign-in is yours, unless you grant support (§4.7)."

Reason: no user key exists (§4.1), and a support grant is the one other way in
(A10). The row must not say "the user's key" while §4.1 says there is none.

### §4.3 — heading and text changed

**v3.7:** "One LUKS keyslot, yours" — one keyslot at handoff.
**v3.9:** "**No human keyslot; the seal.**" `cryptsetup luksDump` shows no
passphrase keyslot; the volume key is sealed to the measured boot and unsealed
by the initramfs hook on every boot. Odile never had a key or a passphrase. The
exact command set lands with ODL-454/ODL-332.

### §4.4 — heading and text changed

**v3.7:** "The boot was measured and checked before you typed" — run the
verifier on your laptop while the machine waits, then `ssh` and type the
passphrase.
**v3.9:** "**The boot was measured, and you checked it before you signed in.**"
The `/verify` page shows, per boot: the measurement, the seal policy, zero usable
user keys, the sign-in hash and no operator key, read from your own machine.
The raw report at `/attestation` carries the release id and the
command line that was measured. Compare the measurement to the one in your ready
email. The certificate fingerprint is in your recovery file (A9), not on
`/verify`. The optional deeper check is the verifier bundle, from your laptop:

```sh
curl -fsSLO https://odile.fyi/odile-verify.tar.gz
echo 'd200329260d66ce4ec545b8d34e05b262c06111ee506449c6c44958937250b53  odile-verify.tar.gz' | sha256sum -c -
tar xzf odile-verify.tar.gz
cd odile-verify && ./odile-verify --expect <measurement from your ready email> https://<slug>.odile.fyi
```

It prints PASS or FAIL, and the hash line proves you got the tarball this
command names. A tenant's report names another chip than the demo's, so the
verifier fetches that report's own VCEK from AMD's KDS and checks it against
the pinned ARK; the machine's release selects its entry in the pin. On PASS,
open the URL and set your sign-in. The independent rebuild is §4.5
(`sev-snp-measure` + `snpguest`).

Reason: the page has no certificate fingerprint and no release-id row
(`/attestation` carries the release in the raw JSON), and the access report it
shows today is a 10 November bench block, not the tenant's own state — so
ODL-473 renders the tenant's report and this row says what is actually there.
The laptop verifier stays as the optional deeper check.

### §4.6 — the path the zero-touch install creates (lands with ODL-472)

**v3.7:** "The installer and app manifest" — `curl -s https://<slug>.odile.fyi/manifest`
and `sha256sum /usr/local/bin/odile-install.sh`, a path the v4 user step placed
by hand (`docs/runbooks/install.md` §12.2).

**v3.9:** the same two commands, on paths the zero-touch first boot creates: the
exact release installer at `/usr/local/bin/odile-install.sh` (0755, root), the
signed release manifest at `/etc/odile/manifest.json` with its `.sig`, and
`/manifest` served from the signed bytes. `sha256sum` must equal
`manifest.installer_sha256`; the first tenant proves it (§6).

Reason: the manual step that created the path is gone. Without the placement the
command fails on a strict-bar tenant and `manifest.installer_sha256` names bytes
that do not exist on the machine. The placement and the release cut are
ODL-472; the tenant proof is ODL-332. The row's prose ("It is signed with
Odile's Ed25519 key … an operator signature, not a hardware measurement") is
unchanged.
