# Provisioning one tenant — the user's boot key, no operator key

ODL-201. One real machine, ordered on 2026-11-09 and left waiting at Servury's
measured initramfs. The tenant's row is written; the first boot is ODL-202 and
the install is ODL-203.

The rule this page records: **the machine is ordered with exactly one SSH key,
the user's boot key**. Measured boot fixes that key in the command line
(`bb.key=…`), so an operator key cannot be added later and none is ever sent.
There is no root password. HQ never opens a session on the machine.

> "The boot key is the one key in the measured command line: generated by you,
> taken at build, asked for at every reboot." — `docs/CLAIMS.md`

The first tenant is Savio himself: `odl-7971a8`, `owner@example.com`.
His boot key is his existing user key — the public half already authorised on HQ
(`/root/.ssh/authorized_keys`), copied to
`/root/.odile/tenants/odl-7971a8.pub` and nowhere else. Its private half is not
on this box. From ODL-231 the claim page collects a fresh key per tenant.

measurement is recorded in this card; ODL-202 derives it.

## 5. The initramfs host key

`ssh-keyscan` is a key exchange, not a login: no key is offered and no session
is opened. The initramfs runs `dropbear_2025.89` on port 22 and offers one
ed25519 host key.

```sh
ssh-keyscan -T 5 -t ed25519 203.0.113.87
# 203.0.113.87 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIPrRFsrcJK1KMAM7+jjBwl/UsD4yi0PjuN1hHnk5C229
ssh-keygen -lf keyscan.txt
# 256 SHA256:DGAwJjsAiHJo/+1jbhOWJ5UUPd2tQj3ZXKAxlo3R8zY 203.0.113.87 (ED25519)
```

That fingerprint is recorded in `tenant_state.initramfs_host_key` at provision.
It is what `odilectl.state.park_for_owner` compares: a stopped heartbeat plus
port 22 offering *this* key is "waiting for the owner"; a different key is
refused loudly, because a changed host key is exactly what the ceremony forbids.

**Stability across a boot was measured.** The same key was observed at
16:03:46Z and again at 16:09:33Z, after the restart in §4:

```
$ ssh-keygen -lf keyscan-after-reboot.txt
256 SHA256:DGAwJjsAiHJo/+1jbhOWJ5UUPd2tQj3ZXKAxlo3R8zY 203.0.113.87 (ED25519)
```

Release 2026.11.1 seals the key to the SNP-derived key. Release 2026.09 and
earlier made a new key on every boot, which is why the pin is 2026.11.1 or
later and why the script exits 5 on an older `measured_release`.

## 6. No SSH session from HQ

The private half of the boot key is not on HQ. The card's evidence command is a
failed authentication, not a session:

```sh
ssh -F /dev/null -o BatchMode=yes -o StrictHostKeyChecking=no \
    -o UserKnownHostsFile=/dev/null -o ConnectTimeout=10 \
    -o PreferredAuthentications=publickey root@203.0.113.87 true
# exit 255
# root@203.0.113.87: Permission denied (publickey).
```

The script runs exactly this command after every successful provision and
**fails if it succeeds**. A success would mean an operator credential exists on
a tenant machine, which breaks the access model.

No private key matching the public half exists on this box: a search of `/root`
for `BEGIN OPENSSH PRIVATE KEY`, outside vendored package trees, finds none, and
`/root/.ssh/authorized_keys` holds only the public line. The machine accepts
exactly the key in its measured command line, so with no private half on HQ
there is nothing to authenticate with.

## 8. Failure modes

| Symptom | Meaning | What to do |
|---|---|---|
| `401` | missing, unknown or inactive reseller key | check `/root/.odile/servury_reseller_key`; nothing charged |
| `402` | insufficient balance or no payment method | top up; nothing changed |
| `409` "Plan is sold out" | no room; `preorder` was false | decide whether the customer will wait; `--preorder` pays now and is **final** |
| `queued` after a pre-order | paid, waiting for capacity; there is no address yet | the row is recorded; rerun `--apply` with the same slug once it is active to verify the flags, the host key and the no-login probe |
| `400` on `ssh_key` | truncated key, pasted password, bad base64 | fix the file; the script's parser refuses the same shapes before the call |
| `400`/`409` on `measured` | the image or flags cannot support measured boot | use `debian13` with `snp`, `fde` and one key |
| `404` on `?action=server` | wrong or terminated id | list `?action=servers` |
| `status: failed` (`status_reason: deploy`) | the build failed; the charge is refunded | terminate the row (`404` afterwards) and order again |
| `measured_release` < `2026.11.1` | the old initramfs regenerates its host key each boot | terminate and reorder on the current release; do not record a key that cannot last |
| no port 22 within `--host-key-timeout` | the initramfs is not up yet, or the machine failed | check `?action=server`, then `?action=serial` with the console log on |
| port 22 offers a different key on a rerun | the initramfs moved (release, address or machine) | the script exits 5; re-record only after understanding why |
| `ssh -o BatchMode=yes` succeeds | an operator key exists on the tenant | hard failure: find how it got there, reinstall without it |
| `504` from `?action=power` | the gateway timed out; the action may still have applied | poll `powered_on`; the initramfs ignores ACPI and the node cuts power after ~90s |
| poll timeout after the create | paid and still deploying/queued | do not re-create: rerun with the same slug, which reuses the machine by hostname |
| a local failure **after** the paid `create` (traceback, nonzero exit) | the machine is ordered and the row may already be committed; the money is spent | do not order again: check `?action=invoices`, then rerun the same slug (it reuses by hostname). Observed 2026-11-09: the first `--apply` paid and provisioned, then died in `record()` with `sqlite3.ProgrammingError: Cannot operate on a closed database` (exit 1); the rows had committed at 16:03:46Z and the 16:04:47Z rerun printed `tenants updated` |
| `balance < price` on a rerun while a machine with this slug exists | the balance check ran before the hostname-reuse lookup (fixed at this head) | at this head the reuse lookup runs first; an old script exits 3 `nothing was charged` although the machine is paid for. Observed 2026-11-09 16:04:18Z: exit 3 at balance 1.66/price 18.99, then exit 0 after the reorder |
| `500` with "paid, but could not record it" | the money was returned to the balance | check `?action=invoices` before retrying |

## 9. Rollback

An active machine is destroyed with `POST ?action=terminate&id=31a63bbb` (no
refund for the days left, address released, `404` within a minute), or
`odilectl destroy odl-7971a8 --apply` once `/root/.odile/config.yaml` exists. A
pre-order cannot be terminated — it is final. `destroy` moves the state row to
`destroyed` and deletes the A record; it does **not** replace the tenant, so the
web row keeps naming the last machine until the rebuild. Re-provisioning is the
**same slug** and a new order (ADR-007): `odilectl provision <slug> --key
<user.pub> --pin odile-verify.pin [--backup-password-file
<the user's old odile-recovery-<slug>.txt>] --apply` reopens the row
(`destroyed -> claimed`), orders the machine, points the web row at its
`server_id` and moves the state row to `first_boot`, so the new machine's first
boot records itself. The URL, the recovery file's name and the
`tenants/<slug>` repository keep their names; the address does not survive —
re-create the A record for the same slug (`docs/runbooks/offboard.md` §5).
`claim._advance_state_provisioned` (`claim.py`) already took the same
`provisioning -> first_boot` step after an order; this path now does too.

## 10. What this page does not prove

- The signed report, the measurement equality and the host-key binding are the
  user's `blackbox-verify` at the ceremony (ODL-202); HQ holds no private key
  and cannot run it.
- The disk is not encrypted yet (`fde_enabled=false`); `encrypt` and `unlock`
  are the first boot.
- The product gate is the Odile sign-in set during the install (ODL-203), not
  this key. The boot key is plumbing: it opens the initramfs and resets a lost
  sign-in on the machine; it is not the Webapp login.
